# 리뷰 체크리스트

리뷰어와 작성자, 셀프 리뷰를 요청받은 에이전트(`AGENTS.md`의 절차)가 함께 쓰는 기준이다. 주간 회고에서 반복된 지적을 여기에 추가한다.

## 공통

- [ ] PR 설명의 "무엇을, 왜"를 본인 말로 썼는가
- [ ] 비밀 정보(API 키, `.env` 값)가 코드나 로그에 없는가
- [ ] 실패했을 때의 동작(오류, 빈 값, 외부 API 실패)을 처리했는가
- [ ] 공통 용어(`COWORK_RULE.md` 3장)를 지켰는가
- [ ] 다른 역할의 영역이나 공통 계약을 바꿨다면 PR에 이유와 영향을 적었는가

## 백엔드

- [ ] 조회·수정·삭제 시 데이터 소유자를 확인하는가 (IDOR)
- [ ] 목록 조회에서 N+1 쿼리가 생기지 않는가
- [ ] 트랜잭션 안에서 외부 API를 호출하지 않는가
- [ ] 응답에 엔티티를 그대로 내보내지 않는가 (DTO 사용)
- [ ] 쿠키 인증 요청에 CSRF 대응이 되어 있는가
- [ ] 입력값을 서버에서 다시 검증하는가
- [ ] 업로드 파일의 크기·개수·경로를 검증하는가

## 프론트엔드

- [ ] 로딩, 성공, 실패, 빈 상태를 모두 처리했는가
- [ ] 이전 요청의 응답이 현재 화면을 덮어쓰지 않는가
- [ ] LLM이 만든 텍스트를 HTML로 직접 넣지 않는가
- [ ] 타이머, 이벤트 리스너, SSE 연결, 녹음을 정리하는가
- [ ] API 키나 외부 AI·음성 API 호출이 프론트엔드에 없는가

## AI 파이프라인

- [ ] 프롬프트를 바꿨다면 평가셋 결과를 첨부했는가
- [ ] LLM 출력을 스키마로 검증하는가
- [ ] 사용자 코드·답변이 지시와 분리되어 전달되는가
- [ ] 코드가 결정해야 할 것(`COWORK_RULE.md` 4장)을 LLM에게 맡기지 않았는가
